# Pixel Agents — Project Skills

Eight skills ported from Claude-Code-Game-Studios and adapted for a single-maintainer, canvas-rendered VS Code extension. They cover the project's known weak spots: sprite/asset consistency, UX spec discipline, canvas/rendering performance, and self-dogfood feedback capture. They are designed to slot above the existing `superpowers:*` workflow (brainstorming → writing-plans → TDD → executing-plans → verification) and alongside `ui-ux-pro-max`, not replace them.

| Skill             | When to use                                                                                                                                                                                                | Replaces (if anything)                                                                                    |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `art-direction`   | Before bulk pixel-art work or when existing art feels inconsistent — writes/updates `docs/art-direction.md`.                                                                                               | source `art-bible` (trimmed from 9 sections to 7, no studio gates)                                        |
| `asset-spec`      | Before drawing a new sprite batch (characters, furniture category/group, floors, walls, UI icons, external pack mapping).                                                                                  | source `asset-spec` (retargeted at `furniture-catalog.json` + PNG pipeline)                               |
| `asset-audit`     | After importing an external pack, after a batch of new furniture, or when the office renders wrong. Scans for catalog drift, orphaned PNGs, electronics miscategorization that breaks work-seat detection. | source `asset-audit`                                                                                      |
| `ux-design`       | Before adding/changing a modal, toolbar, canvas overlay, or flow — writes a section-by-section spec at `docs/ux/<name>.md`.                                                                                | source `ux-design` (added Messaging + Multi-webview sections, removed localization/accessibility-tier)    |
| `ux-review`       | After `/ux-design`, before turning a spec into an implementation plan. Validates messaging protocol + multi-webview safety + art-direction alignment. Read-only.                                           | source `ux-review`                                                                                        |
| `perf-profile`    | When rendering stutters, when the extension host feels slow, or proactively before enabling perf-sensitive features. Static analysis only.                                                                 | source `perf-profile` (retargeted at canvas rAF loop, file watching, hook server, sprite/colorize caches) |
| `playtest-report` | After self-dogfooding a build or trying a new feature end-to-end. Outputs a structured report at `docs/playtests/<date>-<focus>.md`.                                                                       | source `playtest-report` (single-maintainer, no creative-director gate)                                   |
| `quick-design`    | Before small tweaks — constants tuning, a single-rule behavior change, a tiny addition. Under ~2hr and ≤3 files. Writes `docs/quick-specs/<kebab>-<date>.md`.                                              | source `quick-design` (no GDD / balance references)                                                       |

None of these duplicate `superpowers:brainstorming`, `superpowers:writing-plans`, `superpowers:executing-plans`, `superpowers:code-reviewer`, `superpowers:verification-before-completion`, `superpowers:test-driven-development`, or `superpowers:systematic-debugging`. They produce design/spec/audit artifacts; superpowers handles the implementation workflow.
