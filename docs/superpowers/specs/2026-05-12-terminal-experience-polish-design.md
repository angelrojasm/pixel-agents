# Terminal Experience Polish — Design

## Purpose

The in-panel pty terminal (D1 + D2, shipped behind `usePtyTerminal`) now renders agents inside the office, but three rough edges are blocking it from being the default-on experience:

1. Agents have no human-readable name — only a numeric `#id` and the autogenerated `terminalName` (e.g. "Claude Code #2"). Pre-1.3 muscle memory ("rename the terminal") no longer applies, and Claude's own `/rename` is invisible to the office UI.
2. The terminal panel isn't user-resizable. Whatever width the panel was born with is what the user gets, so the terminal often wraps aggressively.
3. The terminal font is the xterm default (system monospace), with no exposed knobs. Users have asked for legibility control.

This spec covers all three as a single shippable bundle. None depend on the others; they share a delivery just because they're small and all live in the same files.

## Decisions

- **Auto-rename from Claude session name, no manual override in v1.** Claude already writes `{"type":"custom-title","customTitle":"<name>","sessionId":"<id>"}` records into the JSONL when the user runs `/rename`. The same record appears as part of the JSONL when a session is `/resume`'d by name. This is the source of truth — we read it instead of inventing a parallel rename UI. A user-overridable display name is deferred to a follow-up if anyone misses it.
- **Splitter drag is the only new resize plumbing.** Pty resize (FitAddon → `ptyResize` message → `PtyManager.resize` → `node-pty.resize`) is already wired end-to-end in `TerminalPane.tsx`, `ptyManager.ts`, `ptyWorker.ts`. Once the user can widen the panel, the terminal will reflow correctly without any backend change.
- **0.5 zoom steps ship unconditionally.** The "integer device-pixels-per-sprite-pixel" invariant produces a known tradeoff at half-steps on low-DPR displays (sprite pixel maps to a non-integer number of device pixels → blur/shimmer). We accept this and let the user evaluate the result in their environment. If half-steps are unusable in practice we'll snap-to-integer at low DPR in a follow-up — but we don't pre-gate.
- **Terminal font: family + size + line-height.** Three knobs, exposed in the Settings modal. No ligature toggle, no letter-spacing slider, no custom-CSS escape hatch in v1.
- **Live-apply throughout.** Every setting takes effect immediately. No "Apply" buttons.
- **Persistence layer matches the value's scope.** Per-agent (`customTitle`) lives in `workspaceState` via `persistAgents()`; user-wide knobs (font family / size / line-height / zoom-step preference) live in `globalState` keys; panel resize is per-window and lives in the existing `panelState` slice persisted to `workspaceState`.

## Item 1 — Auto-rename from Claude session

### Message flow

1. User types `/rename Frontend cleanup` in any Claude terminal (pty or vscode-terminal — both write JSONL).
2. Claude appends `{"type":"custom-title","customTitle":"Frontend cleanup","sessionId":"<id>"}` to the JSONL.
3. `fileWatcher.readNewLines()` picks up the line; `processTranscriptLine()` dispatches by `type`.
4. New branch in `transcriptParser.ts`: `case 'custom-title'` → calls a new `onCustomTitle(agentId, title)` callback that:
   - Sets `agent.customTitle = title` on `AgentState`
   - Calls `persistAgents()` (the title survives reload)
   - Posts `{ type: 'agentRenamed', id, customTitle }` to the broadcast sink
5. Webview `useExtensionMessages.ts` handles `agentRenamed`: sets `character.customTitle` on the matching `Character` in `officeState`.
6. Renderer + ToolOverlay + PanelHeader all prefer `customTitle` over the existing label sources.

### `/resume <name>` case

When the user runs `/resume Frontend cleanup` in a fresh terminal:

- The `SessionStart(source=resume)` hook fires; existing logic in `hookEventHandler.ts:236-258` reassigns the agent to the resumed session's transcript.
- `reassignAgentToFile()` in `fileWatcher.ts:1338` sets `agent.fileOffset = 0` on reassignment, so the new JSONL is read from the top. The `custom-title` record (which lives at or near the top of a resumed session's JSONL) is picked up on the next poll tick, and step 3 above fires.
- No new code is needed for the resume path — it falls out of the existing offset-reset behavior.

### Display priority

Resolved in `characterLabel()` (a tiny helper added to the webview):

```
customTitle ?? agentName /* team role */ ?? terminalName /* "Claude Code #2" */ ?? `Agent #${id}`
```

This keeps the team-role naming feature working (sub-agents/teammates have `agentName` set but no `customTitle`).

### Persistence

- `customTitle?: string` added to `AgentState` and `PersistedAgent`.
- `persistAgents()` already serializes the full record — just include the new field.
- On restore, the title round-trips. If the JSONL still has a more recent `custom-title` line beyond our last offset, we'll see it on next poll.

### Not covered (deferred)

- Manual override / inline editing.
- Renaming sub-agents/teammates independently of their parent's session (they don't have their own Claude session today).
- Auto-suggesting a name from conversation content.

## Item 2 — Splitter drag + 0.5 zoom steps

### Splitter

A 4px-wide drag handle on the panel's office-facing edge. Cursor changes to `ew-resize` (left/right panel) or `ns-resize` (bottom panel). On `mousedown`, capture pointer, listen for `mousemove`, write `state.userBandSizePx = clamp(MIN, newPx, MAX)`. On `mouseup`, release.

`MIN` and `MAX` are constants. `bandSize` is a height when the panel is on the bottom and a width when it's on the left/right; the clamp values map onto whichever dimension applies:

- `PANEL_MIN_OPEN_PX = 240` (applies to both orientations — narrower than this and the agent rail / panel header breaks layout).
- `PANEL_MAX_OPEN_PX_BOTTOM = viewportHeight - 200` — keep at least 200px of canvas above when the panel is on the bottom.
- `PANEL_MAX_OPEN_PX_SIDE = viewportWidth - 360` — keep at least 360px of canvas next to a side panel.

The clamp lives in `computeBand()`. The `Splitter` component just emits raw deltas.

`computeBand()` becomes:

```ts
if (state.userBandSizePx != null) {
  bandSize = clampBandSize(
    state.panelPosition,
    state.userBandSizePx,
    viewportWidth,
    viewportHeight,
  );
} else {
  bandSize = horizontal ? bottomOpenSize(viewportHeight) : sideOpenSize(viewportWidth);
}
```

So the default behavior is preserved for users who never drag; only the moment they drag does the override engage. Double-click on the splitter resets `userBandSizePx = undefined`.

### 0.5 zoom steps

Today, zoom is `ZOOM_MIN` through `ZOOM_MAX` integers (1, 2, 3, …). The new step array becomes `[1, 1.5, 2, 2.5, 3, 3.5, …, ZOOM_MAX]`. `ZoomControls.tsx` `+/-` buttons increment/decrement by one array slot. Direct zoom-to(n) calls (e.g. the auto-fit default) round to the nearest array slot.

The pixel-perfect invariant ("zoom = integer device-pixels-per-sprite-pixel") is **knowingly broken at half-steps when DPR is 1**: sprite_pixel × 1.5 × 1 = 1.5 device pixels → browser interpolates → blur/shimmer along sprite edges. At DPR ≥ 2 (retina), `1.5 × 2 = 3` device pixels, still integer, still crisp.

**Post-ship review checkpoint**: if blur at DPR=1 is unusable, we add a "snap half-steps to integers when `devicePixelRatio < 1.5`" rule in a follow-up. Not pre-gated.

### Persistence

- `userBandSizePx` lives in the existing `panelState` slice (already round-tripped through `panelPersistence.ts`).
- Current zoom value is already persisted; no schema change needed for the half-steps — it's just additional valid values.

## Item 3 — Terminal font customization

### Settings UI

A new **Terminal** subsection in the existing Settings modal (one of the categories that will get re-homed when the settings redesign ships; until then, just another labeled block in the current scroll list).

Controls:

- **Font family** — dropdown:
  - `System default` (CSS `monospace`) — current behavior, default
  - `Fira Code`
  - `JetBrains Mono`
  - `Cascadia Mono`
  - `IBM Plex Mono`
- **Font size** — existing `terminalFontSize`, expose as `[- 13 +]` stepper (range 8–24, current implicit range stays).
- **Line height** — `[- 1.0 +]` stepper (range 0.8–2.0, step 0.1).

### Font delivery

Bundled mono fonts shipped as `.woff2` in `webview-ui/public/fonts/terminal/` and `@font-face`'d in `index.css`. No CDN, no network fetch. Each font is small (~30-50KB woff2). All five total ≤ 250KB added to the webview bundle.

### Wire-through

- `settingsLoaded` message gains `terminalFontFamily: string`, `terminalLineHeight: number`.
- New webview→extension messages: `setTerminalFontFamily { value }`, `setTerminalLineHeight { value }`. Existing `setTerminalFontSize` already exists.
- Extension persists each in `globalState` (per-user, cross-window).
- `TerminalPane.tsx` passes the values into xterm's `Terminal` constructor options (`fontFamily`, `fontSize`, `lineHeight`) and updates them on change.

xterm requires a `term.options.fontFamily = ...; fit.fit();` pair to apply font changes — already known from the existing font-size code path; line-height behaves the same way.

### Not covered (deferred)

- Custom font family text input.
- Font weight, letter spacing, ligature toggle.
- Per-agent font overrides.

## State & Persistence

| Field                | Lives on                                       | Persisted to                               | Default                                       |
| -------------------- | ---------------------------------------------- | ------------------------------------------ | --------------------------------------------- |
| `customTitle`        | `AgentState`, `PersistedAgent`                 | `workspaceState` via `persistAgents()`     | undefined (falls back to `terminalName` etc.) |
| `userBandSizePx`     | `PanelState`                                   | `workspaceState` via `panelPersistence.ts` | undefined (computed from viewport)            |
| Zoom value           | already on webview state                       | already persisted                          | unchanged; values now include `.5`            |
| Terminal font family | `globalState[GLOBAL_KEY_TERMINAL_FONT_FAMILY]` | extension `globalState`                    | `"monospace"` (System default)                |
| Terminal font size   | `globalState` (existing)                       | extension `globalState`                    | unchanged (existing default)                  |
| Terminal line height | `globalState[GLOBAL_KEY_TERMINAL_LINE_HEIGHT]` | extension `globalState`                    | `1.0`                                         |

## Behavior

- **Rename takes effect within ~500ms** of the user pressing Enter in Claude (one JSONL poll tick).
- **Splitter drag updates the band in real time.** PTY reflows on every `ResizeObserver` tick already; expect visible reflow during drag.
- **Zoom change**: re-renders next frame. No animation; this matches existing zoom behavior.
- **Font change**: xterm re-measures; the terminal contents redraw. Brief flicker possible — acceptable.
- **Sub-agents inherit no `customTitle`.** A sub-agent shows its team role label (`agentName`), not the parent's custom title — this matches existing label rules.

## Out of Scope

- Manual rename UI (deferred to v2 if requested).
- Webview-side font upload / custom CSS.
- Zoom snap-to-integer at low DPR (post-ship review may add).
- Settings modal redesign — covered by a separate spec (`2026-05-12-settings-redesign-design.md`).
- Per-agent terminal font (everyone gets the same).
- Color theme for the terminal.

## Implementation Order

1. **JSONL `custom-title` handler** (smallest, highest value).
   - Add `customTitle?: string` to `AgentState` and `PersistedAgent`.
   - Add the `case 'custom-title'` branch in `transcriptParser.ts`.
   - Wire `agentRenamed` message through to webview, render in character label / panel header / overlay.
2. **Splitter drag.**
   - Add `userBandSizePx` to `PanelState` + persistence.
   - `Splitter` component + `OfficePanel` wiring.
   - Clamp in `computeBand()`.
   - Double-click splitter → reset to undefined.
3. **0.5 zoom steps.**
   - Extend `ZOOM_STEPS` array in `webview-ui/src/constants.ts`.
   - Adjust `ZoomControls` increment.
   - Confirm `defaultZoom()` still rounds to nearest array slot.
4. **Terminal font knobs.**
   - Bundle mono `.woff2` files + `@font-face`.
   - Settings modal Terminal block (family dropdown + size stepper + line-height stepper).
   - Plumb messages + globalState keys + wire to xterm options.

Each step ships independently. None requires a coordinated rebuild.

## Compatibility With Phase 3

- All four fields (`customTitle`, `userBandSizePx`, terminal font knobs) flow through messages that already pass through `MessageSink`. The WebSocket replacement inherits them automatically.
- `custom-title` records are part of Claude's JSONL format, which the daemon will still produce in Phase 3 — same parser, same trigger, same UX.
