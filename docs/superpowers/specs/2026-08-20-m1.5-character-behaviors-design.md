# M1.5 — Character Behaviors Port (Design)

> **Status**: Approved scope, designed 2026-08-20
> **Branch**: `m1.5-character-behaviors` (stacked on `m1-standalone-terminals`)
> **Source of truth for ported behavior**: branch `v2-orchestrator` — port, never rewrite.
> **Scope decision (Angel, 2026-08-19)**: four clusters in; hook-health surfacing
> (`hookHealthChanged` + toast) explicitly **deferred** — it needs a newly designed
> server-side health signal, not a port.

## Goal

Port the four v2-only character-behavior clusters onto the upstream-v1.4.1 + M1
base so the office characters behave like they did in v2:

1. **Seat roles + rest behavior** — chairs facing a computer are _work_ seats;
   others are _rest_ seats. Active/awaiting agents walk to their work seat;
   idle agents wander, then go rest on a couch.
2. **PTY-driven animation** — the focused agent's character types in real time
   while pty bytes flow, and reads in the silence between bursts.
3. **Crash visual state** — a crashed agent's character desaturates and shows a
   glyph until clicked; restart clears it; state survives a page reload.
4. **Labels + focus halo + sub-agent linkage** — one label-priority rule
   (customTitle → agentName → terminalName → `Agent #id`), a seat-anchored
   focus halo for the focused terminal's agent, and dashed sub-agent→parent
   link lines while the parent is focused.

Everything lands in the shared webview + server code, so M2 (VS Code surface)
inherits it; in M1.5 the pty-dependent pieces are only _exercised_ by the
standalone surface.

## Cluster 1 — Seat roles + rest behavior

### Seat classification

- New module `webview-ui/src/office/engine/seatAdjacency.ts` (ported from v2):
  `facesComputer(seatCol, seatRow, facingDir, electronicsTiles)` — scans
  `AUTO_ON_FACING_DEPTH` (3) tiles in the facing direction, plus one
  perpendicular tile on each side **at every depth**; and
  `collectElectronicsTiles(furniture, getCategory, getFootprint)`.
- `Seat` (`webview-ui/src/office/types.ts`) gains `role: 'work' | 'rest'`.
  `layoutToSeats` (`layoutSerializer.ts`) computes it:
  `facesComputer(...) ? 'work' : 'rest'`. Seat uid scheme (`uid`, `uid:1`, …)
  is untouched — persisted `seatId` values keep working.

### Character model

- `Character` keeps the base's **`seatId`** field name for the work seat (v2
  called it `workSeatId`; renaming would churn the `saveAgentSeats` protocol
  payload, persistence, test hooks, and e2e helpers for zero behavior — see
  Deviations #1). New fields:
  - `restSeatId: string | null` — transient couch claim; never persisted;
    cleared whenever the character leaves the rest seat or work starts.
  - `awaitingSince: number | null` — the tier-2 awaiting-user latch.
- `shouldBeSeated(ch) = ch.isActive || ch.awaitingSince != null` (ported
  verbatim into `characters.ts`).
- **Spawn default restores v2's spawn-idle**: `createCharacter` starts with
  `isActive: false` (the base spawns `isActive: true`, which with the ported
  sprite rule would show a freshly launched agent "working" before its first
  prompt). Activation flows through the existing `setAgentActive(id,
status === 'active')` call in the `agentStatus` handler — nothing new is
  needed to flip it on.

### Awaiting-user latch (no protocol change)

The base's `agentStatus` message already carries `awaitingInput` (only
meaningful with `status: 'waiting'` — `core/asyncapi.yaml:274-290`). In
`useExtensionMessages`' `agentStatus` handler:
`status === 'waiting' && msg.awaitingInput === true` → `ch.awaitingSince =
Date.now()`; any other status → `null`. The existing 2-second waiting _bubble_
is unchanged — the latch is a separate, persistent field the FSM reads, which
keeps the character at the desk while the agent waits on the user. Two scoped
narrowings vs v2 (Deviations #9): the latch clears **only** on status
transitions (v2 also cleared it on bubble dismissal — the persistent
awaiting-user bubble isn't ported), and the timestamp is `Date.now()` at
receipt rather than a server-supplied `since` (fine because v2's
"Awaiting reply — elapsed" overlay text isn't ported either).

### FSM (ported from v2 `characters.ts`, adapted names)

- **TYPE**: if `shouldBeSeated && restSeatId` → release the rest seat, go IDLE
  (the "leave the couch, work started" transition). If `!shouldBeSeated`:
  count down `seatTimer` (>0), clear the `-1` sentinel, then — rest-seated
  characters stay put; work-seated ones step off after a short
  `STEP_OFF_PAUSE_MIN/MAX_SEC` (0.3–0.8 s) pause and start wandering.
- **IDLE**: `shouldBeSeated` → release any rest claim, path to the work seat
  (or TYPE in place if seatless/unreachable). Otherwise wander; when
  `wanderCount >= wanderLimit` **and `!ch.isSubagent`** (sub-agents are
  transient and must not occupy couches — see the removal-leak note below),
  claim the **nearest free rest seat** (Manhattan; `findNearestFreeRestSeat`
  in `characters.ts`) — claim FIRST, temporarily unblock the rest tile,
  pathfind, and **roll the claim back if no path** (ordering is load-bearing:
  porting it out of order leaks permanently assigned rest seats).
- **WALK**: on arrival at the rest tile → sit, face `rest.facingDir`, reset
  `wanderCount`, re-roll `wanderLimit`; if the rest seat was lost mid-travel,
  release the claim and go IDLE. Arrival anywhere else while `!shouldBeSeated`
  goes IDLE with the step-off pause when standing on a chair tile
  (`isChairTile`), else the normal wander pause. Mid-walk repath to the work
  seat when `shouldBeSeated` flips true (releasing any rest claim).
- Constants ported: `STEP_OFF_PAUSE_MIN_SEC`, `STEP_OFF_PAUSE_MAX_SEC`. The
  base's return-to-own-seat rest branch (wander → sit at the work seat for
  `SEAT_REST_MIN/MAX_SEC`, 120–240 s) is **replaced** by the rest-seat claim —
  that branch and both constants are deleted (knip flags orphans; Deviations
  #4).

### OfficeState integration

- `addAgent` / `findFreeSeat(folderName)`: keep the base's 3-stage area-zone
  staging, but every stage filters to `role === 'work'`, followed by a **final
  fallback stage that accepts any free seat regardless of role**. Without the
  fallback, an upstream user's layout whose chairs face no electronics (all
  seats classify rest) would strand every agent seatless — a silent
  post-upgrade regression. With it, computer-less layouts degrade gracefully
  to upstream's current any-chair behavior. Teammate seating
  (`closestFreeSeat`) applies the same prefer-work-then-any rule. The base's
  `pickFromSeats` electronics bias is removed — the role filter subsumes it
  (the role IS "faces electronics"), so `isSeatFacingElectronics` in
  `officeState.ts` is deleted. Both `layoutToSeats` and the auto-on logic
  consume the shared `collectElectronicsTiles`, but their windows stay
  deliberately different (v2 parity): seat roles use `facesComputer`'s
  side-check-at-every-depth rule; `rebuildFurnitureInstances`'s auto-on keeps
  its own `AUTO_ON_SIDE_DEPTH` (2) sweep. `preferredSeatId` honored only if
  free **and** work-role.
- `reassignSeat`: clicking a rest seat is a no-op (`role !== 'work'` guard) —
  the guard stays strict even though auto-assignment can fall back to rest
  seats; manual reassignment is a deliberate act and couches are for resting
  (v2 semantics).
  `renderSeatIndicators` renders rest seats with `SEAT_BUSY_COLOR` regardless
  of occupancy — never `SEAT_AVAILABLE_COLOR`, matching the click semantics.
- `removeAgent` frees **both** `seatId` and `restSeatId` seats.
  `removeSubagent` / `removeAllSubagents` free `restSeatId` too — defensive
  belt beside the `isSubagent` claim gate, since a leaked
  `seat.assigned = true` survives until the next layout rebuild.
- `rebuildFromLayout`: pass 1 re-claims a kept seat only if it still exists,
  is free, **and is still work-role** (a chair whose monitor was deleted
  demotes to rest, and its occupant is re-seated in pass 2). `restSeatId` is
  cleared (and its seat freed) for **all** characters at the top of the
  rebuild — v2 only cleared it for characters that lost their work seat, which
  left a dangling claim that froze the character at its desk until the next
  turn (Deviations #3).
- `walkToTile` / `withOwnSeatUnblocked` cover both seat tiles (own work seat +
  claimed rest seat), as in v2.
- Pets, headless ghosts, and the greeter are untouched: pets never take seats,
  headless agents occupy seats normally, the greeter lives outside
  `characters`.

## Cluster 2 — PTY-driven animation

- `Character.ptyActivityUntil: number` (init 0), a raw mutation — no React
  re-render per byte, the renderer polls `Date.now()` each frame (v2's
  deliberate design).
- New hook `webview-ui/src/office/panel/useCharacterPtyActivity.ts` (v2's
  location, beside the bus): subscribes to the **focused terminal's** agent on
  the existing
  `PtyEventBus.ptyActivity` fan-out (M1 already ships it with zero
  subscribers). Throttles bumps to one per `PTY_ACTIVITY_THROTTLE_MS` (50 —
  v2's hardcoded literal, now named; Deviations #6), then
  `ch.ptyActivityUntil = Date.now() + PTY_ACTIVITY_HOLD_MS` (200).
  The throttle+deadline decision is extracted as a pure function in the same
  module for node-runner tests; v2's parallel `ptyActivityReducer` (used only
  by its own test) is **not** ported (Deviations #4).
- `getCharacterSprite` TYPE branch becomes v2's exact ordering:
  1. `!ch.isActive` → static standing pose `walk[dir][1]` (couch rest /
     between turns) — new to the base, which currently animates typing even
     when inactive;
  2. `ch.currentTool` → tool-driven reading/typing (unchanged — tools outrank
     pty);
  3. `Date.now() < ch.ptyActivityUntil` → typing;
  4. else → reading.
     `isActive` gates pty entirely: a non-active character never animates from
     pty bytes.
- Only the focused agent is subscribed (v2's deliberate perf choice);
  non-focused active agents show the reading pose in the no-tool case.

## Cluster 3 — Crash visual state

### Character state + rendering

- `Character.crashed: boolean`, `crashedAcknowledged: boolean`.
- `OfficeState.setAgentCrashed(id, crashed)` — always resets
  `crashedAcknowledged = false` (re-crash re-glyphs), and propagates to live
  sub-agents of that parent in both directions (set + clear), skipping
  despawning ones. `OfficeState.acknowledgeCrash(id)` sets the ack flag.
- Rendering (ported):
  - **Desaturation**: `getCharacterSprites(palette, hueShift, crashed)` gains
    the third param; cache key becomes `${palette}:${hueShift}` +
    `':crashed'` suffix. New `desaturateSprites.ts` applies
    `adjustSprite(sprite, {h:0, s:-CRASHED_DESATURATION_PCT, b:0, c:0})`
    (60%) to all frames. Desaturation keys on `crashed` only — it persists
    after acknowledgement; only the glyph respects `crashedAcknowledged`.
  - **Glyph**: small filled square near the character's head, drawn at
    `zY = charZY + 1`, gated `!isEditMode && crashed && !crashedAcknowledged`,
    skipped during matrix effects. Constants ported; `CRASHED_GLYPH_BG` becomes
    a literal `#d14249` in `constants.ts` — v2 assigned `var(--color-danger)`
    to `ctx.fillStyle`, which canvas silently ignores (Deviations #5).

### Message flow (webview)

The pty fast-path in `useExtensionMessages` (`toPtyEvent` → bus → early
return) stays, but two cases gain an office-state side effect **before** the
return: `agentCrashed` → `os.setAgentCrashed(id, true)` (guarded on
`os.characters.has(id)` — drop if already closed), `agentRestarted` →
`os.setAgentCrashed(id, false)`. The pane-local crash UI in `TerminalPane`
(Restart button recolor) is unchanged.

### Acknowledgement + multi-tab convergence (protocol addition)

Any click on a crashed character's body acknowledges (no separate glyph
hit-box): `App.handleClick` calls the ack path before focusing. Ack round-trips
through the server so multiple standalone tabs converge:

- New ClientMessage **`acknowledgeCrash { type, id }`** — accepted from
  **privileged** connections only (unprivileged viewers never see crash state
  and must not clear glyphs on others' screens).
- New ServerMessage **`crashAcknowledged { type, id }`** — broadcast, delivered
  to **privileged sockets only**. The delivery gate in `httpServer.ts` is
  `PRIVILEGED_ONLY_TYPES = /^pty/` plus a hard-coded `agentCrashed`;
  `crashAcknowledged` must be added to that condition by hand.
- The webview applies its own ack optimistically (v2 behavior) and also on the
  broadcast.

### Reload persistence (protocol addition)

M1's reaping model retains dead workers server-side, so the server knows which
agents crashed. `existingAgents` gains **`crashedAgentIds?: number[]`**
(abnormal exits minus intentional stops, read from the pty host), included
**only in replies to privileged connections**. The webview applies
`setAgentCrashed(id, true)` for each when reconciling existing agents.
`crashedAcknowledged` deliberately resets on reload — a reload re-glyphs
(v2 semantics).

## Cluster 4 — Labels + focus halo + sub-agent linkage

### terminalName reaches the webview (protocol addition)

- `agentCreated` gains **`terminalName?: string`**. The standalone server
  already builds `"Claude Code #N"` (`launchAgentStandalone.ts`). **Only the
  standalone emit site (`httpServer.ts`) sends it in M1.5** — the VS Code
  adapter defers to M2, which keeps the "VS Code surface untouched" gate
  intact and sidesteps a Playwright strict-mode double-match risk in three
  existing VS Code specs that locate the real terminal tab via
  `getByText(/Claude Code #\d+/)`. The field is optional, so the shared yaml
  addition is harmless to the VS Code path.
- `existingAgents` gains **`terminalNames?: { [agentId]: string }`** beside the
  existing `customTitles`.
- Webview stores them in a `terminalNames: Record<number, string>` beside
  `customTitles` (base pattern). No rename polling and no
  `agentTerminalNameChanged` message in M1.5 — standalone terminal names are
  fixed at creation; live VS Code rename tracking is M2's problem.

### One label rule

- Pure `characterLabel({customTitle, agentName, terminalName, id})` ported
  verbatim into `characters.ts`: `customTitle ?? agentName ?? terminalName ??
`Agent #${id}``. **`??`, not `||`** — an empty-string title wins over
  terminalName (v2 contract, pinned by test).
- Rail/band labels (`App.tsx` `railAgents`) switch from
  `customTitles[id] ?? 'Agent #id'` to `characterLabel(...)` — an unnamed
  standalone agent now shows "Claude Code #1" instead of "Agent #1", closing
  the M1 known limit.
- `ToolOverlay` name row shows `customTitle ?? terminalName` — **not** the full
  `characterLabel` — because the base overlay already renders `agentName` as
  its own team-role row, and v2's rule would print the same name twice
  (Deviations #7). Sub-agents keep showing no name row.

### Focus halo

- `webview-ui/src/office/engine/characterHalo.ts` ported verbatim:
  `getFocusHaloStyle({isActive, isFocused, awaitingSince})`, five branches in
  priority order (focused+awaiting → amber solid; active+focused → accent
  solid; active+unfocused → muted solid; focused idle → accent dotted; else
  none), `FOCUS_HALO_WIDTH_PX = 2`.
- Renderer: halo strokes a rect around the agent's **work-seat tile** (falls
  back to the character tile when seatless), `zY = charZY −
2·OUTLINE_Z_SORT_OFFSET`, gated `!isEditMode && !ch.isSubagent`, skipped
  during matrix effects. Inset/width intentionally not zoom-scaled (v2 visual
  parity).
- Focus source: the base's `focusedTerminalId` (App state) — passed into
  `OfficeCanvas` and threaded through the existing `SelectionRenderState`
  object, **not** as a new positional `renderFrame` parameter (it has 20
  already).
- Halo colors are new named constants in `constants.ts` with literal values
  (accent `#4ade80`, muted `#6b7280`, awaiting `#f59e0b`) — the
  `no-inline-colors` rule requires it.

### Sub-agent → parent dashed lines

Ported: while the focused agent has live sub-agents, a dashed line
(`SUBAGENT_LINK_DASH [2,2]`, width 1, muted color) is drawn from each
sub-agent's center to the parent's center at `zY: 0` (under everything except
floor), gated `!isEditMode`. Uses the base's existing `subagentMeta` map. The
dead v2 constant `SUBAGENT_LINK_FLASH_DURATION_MS` is not ported.

### Click flow

Unchanged base flow (canvas click → select + camera follow → `App.handleClick`
→ sub-agent parent redirect → `focusAgent` + `setFocusedTerminalId` when
pty-backed), with one insertion: crash ack (Cluster 3) before focusing. The
halo closes the click-as-focus visual loop in both directions (canvas click
and rail-tab click both move it).

## Deviations from v2 (deliberate)

1. **Keep `seatId`, don't rename to `workSeatId`** — the name is baked into the
   `saveAgentSeats` protocol payload, persistence, test hooks, and e2e
   helpers; renaming is churn with zero behavior. `restSeatId` lands beside it.
2. **`findFreeSeat` keeps the base's area-zone staging** (v2 predates Areas),
   filtered to work seats; v2's uniform-random `findFreeWorkSeat` is not
   ported.
3. **`rebuildFromLayout` clears `restSeatId` for all characters** — fixes v2's
   dangling rest-claim freeze after a layout edit.
4. **Dead-in-v2 code is not ported, and the base code it supersedes is
   deleted**: `PTY_SILENCE_TO_READING_MS`, `SUBAGENT_LINK_FLASH_DURATION_MS`,
   and `ptyActivityReducer.ts` (dead in v2) are not ported;
   `SEAT_REST_MIN/MAX_SEC` — dead in v2 but **live in the base's
   return-to-own-seat rest branch** — are deleted along with that branch,
   which the rest-seat claim replaces.
5. **`CRASHED_GLYPH_BG` is a hex literal** — v2 fed `var(--color-danger)` to
   canvas, which silently no-ops.
6. **The 50 ms activity throttle becomes `PTY_ACTIVITY_THROTTLE_MS`** — v2
   hardcoded the literal with a stale comment.
7. **ToolOverlay name row is `customTitle ?? terminalName`** — the upstream
   overlay already shows `agentName` as a role row; v2's full label rule would
   duplicate it. The full rule still governs rail/band labels.
8. **Crash ack and crash reload state ride the protocol** (v2 used the
   daemon's snapshot replay, which doesn't exist here) — `crashAcknowledged`
   broadcast + `existingAgents.crashedAgentIds`. v2's `crashReducer.ts`
   (pane-level crash records) is superseded by M1's `TerminalPane` crash UI
   plus this protocol-carried state, and is not ported.
9. **The awaiting-user latch clears only on status transitions** (v2 also
   cleared it via bubble dismissal, but the persistent awaiting-user bubble
   isn't ported), and stamps `Date.now()` at receipt instead of a
   server-supplied `since` (the elapsed-time overlay text isn't ported).
10. **Spawn-idle is restored** (`createCharacter` starts `isActive: false`, as
    in v2) — a change to the base's current spawn-active default, not to v2.

## Testing

**Webview unit (node runner, `webview-ui/test/`)** — ports of v2's suites plus
new coverage for the FSM gap (the base has no `characters.test.ts`):

- `seat-classification.test.ts` (port): `facesComputer` window edges;
  `layoutToSeats` roles — chair+desk+monitor → work, chair+bare desk → rest,
  2-wide couch → two rest seats (`uid`, `uid:1`); reuses v2's
  `installTestCatalog` fixture.
- `rest-seat-fsm.test.ts` (new): drives `updateCharacter` — wander→claim→sit;
  claim rollback on unreachable rest seat (no leaked `assigned`); leave couch
  on `isActive`; `awaitingSince` keeps the character seated; step-off pause
  after turn end; rebuild clears rest claims; sub-agents never claim rest
  seats and `removeSubagent` frees a stale claim; a layout with only rest
  seats still seats agents via the fallback (and prefers work seats when both
  exist).
- `character-halo.test.ts` (port): all five style branches by exact constant.
- `desaturate-sprites.test.ts` (port): 0% passthrough, 60% keeps hue dominant,
  100% grayscale, alpha-suffix preservation.
- `crash-state.test.ts` (new): `setAgentCrashed` sub-agent propagation both
  directions, ack reset on re-crash, despawning subs skipped.
- `character-label.test.ts` (new): priority order incl. the empty-string `??`
  contract.
- `pty-activity.test.ts` (new): the pure throttle/deadline helper.

**Server (Vitest)**: `existingAgents` reply carries `crashedAgentIds` for
privileged connections and omits it otherwise; intentional stops excluded;
`acknowledgeCrash` dispatch → `crashAcknowledged` broadcast; unprivileged
`acknowledgeCrash` rejected; `crashAcknowledged` withheld from unprivileged
sockets (extend `httpServerWs` gate tests); the standalone `agentCreated`
carries `terminalName` and the VS Code path does not (M2).

**E2E (standalone, mock-claude)**: unnamed spawn shows "Claude Code #1" in the

`crashed: true` via the `getCharacters()` test hook and recovers on Restart;
reload re-glyphs (crashedAgentIds path). Rest-seat wandering and halo
rendering stay at unit level — wander timing (2–20 s) and canvas-pixel
assertions are poor e2e fits; the `getCharacters()` test hook gains
`crashed`, `crashedAcknowledged`, and `restSeatId` fields (the crash e2e
asserts on the first two), and `getSeats()` gains `role`.

**Gates**: `npm run compile`, full server + webview vitest, e2e standalone
slice, the hooks-off VS Code slice (extension surface must stay untouched),
knip, format, asyncapi validate + drift, e2e inventory drift.

## Out of scope

- Hook-health surfacing (deferred by scope decision).
- v2's awaiting-user **surface** behaviors: the persistent `awaiting-user`
  bubble sprite, the "Awaiting reply — elapsed" overlay text, and
  always-show-label for awaiting agents. Only the seating latch is ported.
- VS Code emission of `terminalName` (M2, with live rename tracking).
- `agentTerminalNameChanged` live rename tracking (M2, VS Code).
- Client-side rename UI (`renameAgent` ClientMessage) — `agentRenamed` remains
  server→client only.
- The v2 "pty-stub halo variant" (deferred in v2 itself, stays deferred).
- Making crash state visible to unprivileged viewers.
